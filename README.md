# Harness Widget

[English](README.en.md) · **Русский**

Компактная оконная оболочка для **уже работающего** веб-хоста DeepSeek Harness.

Виджет не запускает свой харнесс и не подменяет его: он подключается к тому же серверу
(`http://127.0.0.1:3080`), поэтому профиль, список сессий, история и текущий диалог —
те же, что при работе в браузере. Просто без браузера: узкая панель у правого края,
поверх остальных окон, с треем и горячей клавишей.

## Требования

- Windows 10 или 11 (проверено на Windows 11 26200). Прозрачность фона требует включённых
  «Эффектов прозрачности» Windows: *Параметры → Персонализация → Цвета → Эффекты прозрачности*.
- Node.js 18+ и npm — только чтобы установить зависимости.
- Запущенный харнесс, доступный на `127.0.0.1:3080` (`npx @deepseek-ai/dsh web`).
  Виджет его не запускает и не останавливает, если не настроен путь к лаунчеру.

## Установка

```powershell
git clone <адрес этого репозитория> HarnessWidget
cd HarnessWidget
npm install
copy config.example.json config.json   # затем поправьте значения под себя
```

Если `npm install` зависает на загрузке бинарника Electron — скачайте архив вручную и
распакуйте его в `node_modules\electron\dist`, положив рядом файл `path.txt` со строкой
`electron.exe`. Именно так устанавливался Electron для этого проекта.

## Запуск

```powershell
npm start
```

Или двойным кликом по `Start-Widget.cmd`. Окно откроется панелью у правого края экрана.

## Управление

| Действие | Как |
|---|---|
| Показать / скрыть | `Ctrl+Space` (настраивается) или клик по иконке в трее |
| Начать писать | `Ctrl+Shift+Space` (настраивается) — открывает виджет и ставит курсор в поле ввода |
| Компактная панель / полное окно | кнопка в шапке или пункт меню трея |
| Поверх всех окон | кнопка-«булавка» в шапке |
| Обновить страницу | кнопка «⟳» в шапке |
| Скрыть в трей | «✕» в шапке |
| Выход | меню трея → «Выход» |
| Запустить / остановить харнесс | меню трея (вызывает `Start-Harness.ps1` / `Stop-Harness.ps1` лаунчера) |

Окно без рамки: шапка виджета — своя, её можно тянуть мышью. Размер и позиция
свободного окна запоминаются между запусками.

### Положение и размер окна

Виджет запоминает геометрию, которую ты задал сам — перетаскиванием за шапку или
растягиванием за края в Windows. Закрыл и открыл по горячей клавише — окно вернётся
на то же место и в том же размере. Позиция хранится в
`%APPDATA%\harness-widget\window-state.json`.

Два случая, когда запомненное положение забывается намеренно:

- движение ползунков «Ширина панели» и «Высота панели» — это явное указание размера,
  оно важнее ручной правки;
- кнопка «Вернуть на место» в настройках или пункт меню трея «Вернуть панель к правому
  краю».

Если монитор, на котором стояло окно, отключился, границы проверяются и подгоняются
под оставшиеся экраны.

### Анимация появления

При показе окно выезжает из-за правого края экрана, при скрытии уезжает обратно.
Двигается только позиция, размер не меняется, поэтому раскладка не пересчитывается
и движение ровное. Длительность — 240 мс с торможением к концу.

Выключить можно переключателем «Анимация появления» в настройках. Тогда окно
появляется и исчезает мгновенно.

### Горячая клавиша

Кнопка с сочетанием в разделе «Интерфейс»: нажми на неё, затем нажми новое сочетание —
оно применится сразу. `Esc` отменяет запись, `Backspace` возвращает значение по умолчанию.

Принимаются сочетания с модификатором (`Ctrl`, `Alt`, `Shift`, `Win`) или функциональные
клавиши `F1`–`F24`: одиночные буквы и цифры не годятся — такое сочетание перехватывало бы
обычный ввод. Если сочетание занято другой программой, виджет сообщит об этом и оставит
прежнее.

### Стеклянный фон

Панель рисуется поверх системного материала окна: DWM размывает то, что находится позади.
Тон поверх стекла задают два ползунка: «Прозрачность фона» для самой панели и
«Прозрачность поля ввода» для карточки с полем ввода — она всегда плотнее фона, чтобы
текст оставался читаемым. Меню и всплывающие панели остаются непрозрачными.

Стекло видно настолько, насколько контрастно то, что позади. Над ровным тёмным фоном
размывать нечего — панель будет выглядеть просто тёмной; эффект проявляется, когда за
виджетом есть светлые или цветные окна.

Два условия, без которых стекла не будет видно:

1. **Windows 11 22H2 или новее** — материал Acrylic поддерживается только там.
2. **Включённые эффекты прозрачности Windows**: Настройки → Персонализация → Цвета →
   Эффекты прозрачности.

Переключение режима пересоздаёт окно: прозрачность окна задаётся только при его создании,
поэтому страница перезагружается. Сессия живёт на сервере и возвращается на место.

## Настройка через файл

`config.json` рядом с `package.json`:

```jsonc
{
  "launcherDir": "F:\\Automatic Harness Runner", // откуда брать токен и скрипты запуска
  "url": "",                                     // явный адрес; пусто — взять из состояния лаунчера
  "hotkey": "Control+Alt+H",
  "panelWidth": 440,                             // ширина компактной панели, px
  "panelHeightRatio": 0.3333,                    // высота панели долей от рабочего стола (1/3 экрана)
  "zoomPanel": 1.6,                              // масштаб интерфейса в панели (0.8 — исходный)
  "zoomWindow": 1,                               // масштаб интерфейса в полном окне
  "menuScale": 1,                                // масштаб меню сессий
  "modelScale": 1,                               // масштаб диалога выбора модели
    "showOnStartup": false,                        // открывать окно сразу при входе в Windows
  "popupOnAnswer": true,                          // всплывать, когда агент закончил отвечать
"alwaysOnTop": true
}
```

Эти же значения правит окно настроек, так что файл можно не трогать.

Панель пришвартована к правому нижнему углу. `panelHeightRatio` меняет высоту:
`0.5` — половина экрана, `1` — во всю высоту.

## Косметика интерфейса харнесса

Файл `src/widget.css` применяется к странице внутри виджета и не затрагивает браузер.
Сейчас там такие правки:

- поле ввода растянуто на всю ширину панели и стоит ровно по центру;
- поле ввода поднято от нижнего края: нижний отступ в 1,5 раза меньше бокового;
- подсказка внутри поля ввода убрана;
- поле ввода компактное в пустом виде и растёт под набранный текст (минимум 28px —
  одна строка; после 336px контейнер начинает прокручиваться);
- в пустой сессии скрыта декоративная шапка (крупный логотип и строка режимов) —
  при увеличенном масштабе она не давала карточке ввода поместиться в панель;
- группа с выбором модели прижата вправо и переносится на отдельную строку, если
  перестаёт помещаться; сама кнопка показывает значок в стиле соседних иконок
  строки — приглушённый текст и тонкий контур вместо заливки: тариф модели
  (`FLASH`, `PRO`, иначе код вида `V41`) и буква режима рассуждений в контурном
  кружке — `O` выключен, `L` низкий, `H` высокий, `M` максимальный; полное
  название модели — в подсказке при наведении;
- панель настроек самого харнесса и его страницы (Plugins и прочие) получают
  натуральный размер: при крупном масштабе страницы их вёрстка не помещалась в панель
  виджета, и текст рвался по слогам. Масштаб компенсируется, страницы занимают всю
  ширину и высоту окна, а переписка сохраняет увеличенный масштаб;
- карточки и пузыри переписки полупрозрачны, причём плотность задана в CSS — карточка
  не успевает мелькнуть непрозрачной. Стекло разрешено только в ленте переписки и в
  поле ввода; всё остальное скрипт принудительно делает плотным. Это не зависит от
  названий классов: любая панель, меню или подсказка харнесса останется читаемой.
  Дополнительно помечаются контейнеры всплывающих окон и их фоновые подложки
  (у харнесса фон меню — отдельный элемент с прозрачностью 45 %). Блоки кода,
  редакторы и поля ввода тоже плотные;
- всплывающая карточка с правками файла расширена на всю ширину окна и прижата к
  левому краю: штатных 244px не хватало, строки диффа резались. Фон у неё плотный,
  шрифт диффа 10px — так строки помещаются целиком и читаются. Всплывающие окна
  вообще исключены из правил прозрачности: они должны быть плотными;
- развёрнутое меню сессий всплывает поверх содержимого, как выдвижная панель: в узкой
  панели колонка меню забирала почти всю ширину и ломала страницы. Закрывается кликом
  по любому месту вне меню (по чату) или клавишей `Esc`, а не только по кнопке;
  закрывающий клик гасится, чтобы он не сработал заодно и по содержимому под меню;
- левая рейка иконок убрана: контент занимает всю ширину, сверху слева остаётся только
  логотип DeepSeek. Клик по нему разворачивает сайдбар с сессиями (это его штатная
  кнопка-переключатель). Рейка нарисована наложением и мышь не перехватывает —
  кликабельна только кнопка с логотипом, остальная полоса пропускает клики к содержимому;

Масштаб страницы задаётся в `config.json`: `zoomPanel` для компактной панели и
`zoomWindow` для полного окна. Значение — это множитель к размеру 100 %: при `1.6`
интерфейс рисуется вдвое крупнее исходного `0.8`.

Селекторы используют суффиксы CSS-модулей (`[class*="_composerSeat"]`), поэтому переживают
пересборку фронтенда. Состояние сайдбара различается маркером `_collapsed` на его корне:
правила спрятанной рейки действуют только в свёрнутом виде, в развёрнутом сайдбар
открывается штатно.

Состояние окна (режим, размеры, закрепление) хранится в
`%APPDATA%\harness-widget\window-state.json`.

## Как работает авторизация

Харнесс принимает токен только в `GET /`, после чего ставит подписанную cookie на 30 дней
и редиректит на чистый адрес. Виджет при каждом подключении читает свежий адрес с токеном
из `state/harness.json` лаунчера, поэтому после перезапуска харнесса переавторизация
происходит сама. Если сервер ещё не поднялся, виджет показывает заглушку и повторяет
попытки каждые 5 секунд.

## Автозапуск

Меню трея → «Запускать при входе в Windows». Виджет прописывается в автозагрузку
пользователя (ветка реестра `HKCU\...\CurrentVersion\Run`) с флагом `--hidden`: при входе
в систему он стартует **скрытым и ждёт в трее**, не открывая окно. Дальше его вызывает
горячая клавиша (`Ctrl+Space` по умолчанию) или клик по значку в трее.

Если нужно, чтобы окно открывалось сразу при входе, включите в меню трея пункт
«Открывать при входе сразу» — флаг `--hidden` из автозапуска уберётся.

Выключить автозапуск — снять галочку у того же пункта. Либо ярлык на
`node_modules\electron\dist\electron.exe` с аргументами: путь к папке виджета и `--hidden`.

Проверить, что записалось, можно так:

```powershell
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' |
  Select-Object -ExpandProperty 'electron.app.Electron'
```

## Сторонние ресурсы

Ничего, кроме перечисленного ниже, в проекте не используется: своих шрифтов, иконок и
картинок нет, все ассеты рисуются кодом.

| Ресурс | Где используется | Лицензия / статус |
|---|---|---|
| [Electron](https://www.electronjs.org/) 44.5.1 | Единственная зависимость. Рантайм окна: `BaseWindow`, `WebContentsView`, трей, глобальные горячие клавиши, системный материал окна | MIT |
| [Node.js](https://nodejs.org/) 18+ и npm | Запуск виджета и установка зависимости. В рантайме используется только встроенный модуль `node:path`/`node:fs` | MIT |
| [@deepseek-ai/dsh](https://www.npmjs.com/package/@deepseek-ai/dsh) (DeepSeek Harness) | **Не поставляется** с виджетом и не входит в его зависимости. Виджет подключается к уже запущенному локальному веб-хосту харнесса, как это делает браузер | © DeepSeek, лицензия проекта харнесса |
| [npmmirror](https://npmmirror.com/mirrors/electron/) | Зеркало, с которого один раз вручную скачивался бинарник Electron (установщик npm зависал). В коде проекта не используется | Публичное зеркало |
| Windows DWM (`DwmGetWindowAttribute`, системные материалы окна) | Размытие/прозрачность фона окна и диагностика материала | Системный API Windows |
| Системные шрифты Windows | Вся типографика виджета. Своих шрифтов проект не несёт | Системные |

**Отдельно про оформление.** Виджет настраивает внешний вид страницы харнесса, обращаясь к
CSS-классам его интерфейса по суффиксам модулей (`[class*="_composerSeat"]` и подобным).
Это не библиотека и не форк: код харнесса не копируется и не распространяется. Хеши в
классах принадлежат сборке харнесса и могут измениться в новой версии — тогда часть
косметики перестанет применяться, пока селекторы не будут поправлены.

Иконка трея генерируется скриптом `tools/make-icon.js` примитивами Canvas — сторонних
графических файлов в репозитории нет.

## Всплытие при ответе агента

Пока агент работает, кнопка отправки называется «Queue message», а в ленте есть маркер
выполнения. Когда ответ готов, виджет ловит этот переход и, если окно спрятано в трее,
сам выводит его из-за края — можно заниматься чем угодно и не проверять вручную.

Работает и вместе с автозапуском: виджет стартует скрытым, ждёт в трее и появляется
в момент, когда агент закончил отвечать, либо по горячей клавише.

Выключается переключателем «Всплывать при ответе агента» в настройках.

## Значок в трее и уведомления

Значок в трее показывает состояние агента без открытия окна:

| Значок | Что значит |
|---|---|
| Обычный | Агент свободен |
| С янтарной точкой | Агент работает над ответом |
| С зелёной точкой | Ответ готов — окно ждёт |

Как только окно получает фокус, зелёная точка сменяется обычной. В подсказке при наведении
видно название сессии, а пока агент работает — ещё и сколько времени прошло.

Меню трея: **«Остановить агента»** (доступно только во время работы), **«Настройки»** и
**«Открыть журнал»**.

Если ответ пришёл, пока окно было спрятано, виджет всплывает и дополнительно показывает
**уведомление Windows** с первыми строками ответа — часто хватает одного взгляда, чтобы понять
суть. Клик по уведомлению открывает виджет и сразу ставит курсор в поле ввода. Уведомление и
звук к нему выключаются отдельными переключателями в настройках.

## Журнал и восстановление

Виджет пишет свой вывод в `%APPDATA%\harness-widget\widget.log` — при запуске через `.cmd`
консоли не видно, и без журнала разбираться с ошибками нечем. Файл подрезается, чтобы не расти
бесконечно, а открыть его можно из меню трея.

Если харнесс перезапустился, виджет проверяет адрес каждые 15 секунд и подключается заново сам,
как только сервер снова отвечает.

## Портативная сборка

Виджет можно собрать в папку, для запуска которой не нужны Node.js и npm:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-portable.ps1
```

На выходе `dist\HarnessWidget\` с рантаймом Electron внутри и `dist\HarnessWidget-portable.zip`.
Внутри две команды: `HarnessWidget.cmd` — обычный запуск, `Автозапуск.cmd` — прописать
автозагрузку Windows с ожиданием в трее.

Размер архива около 100 МБ: большую часть занимает сам Electron.

**Про предупреждение Windows.** Сборка не подписана сертификатом, поэтому SmartScreen может
показать «Неизвестный издатель» при первом запуске. Подпись требует платного сертификата,
поэтому честнее предупредить об этом здесь, чем обещать подписанный установщик.

## Ограничения

- **Нет харнесса — нет виджета.** Своей копии харнесса у виджета нет: он только подключается
  к локальному серверу.
- **Прозрачность.** Полная прозрачность окна Windows возможна лишь при включённых эффектах
  прозрачности системы. Размытие фона (вариант «Acrylic») добавляет собственную тёмную
  подложку, поэтому по умолчанию оно выключено.
- **Сворачивание правой панели** занимает около 350 мс — это анимация самого харнесса;
  виджет показывает переписку сразу после её завершения.
- **Захват экрана** сторонними средствами (GDI) не видит окно, если поверх него открыта
  игра в эксклюзивно-полноэкранном режиме. На работу самого виджета это не влияет.
- **Только Windows.** Материалы окна и часть поведения завязаны на Windows; на других
  платформах код не проверялся.
